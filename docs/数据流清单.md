# 于你 Yewne — 数据流清单

> 用途：给撰写隐私政策的人提供事实依据。PIPL 要求向第三方提供个人信息时**具名告知**
> （名称、处理目的、方式、信息种类），笼统写"可能与第三方共享"通常不够。
>
> 依据：**照代码实测整理，不是设计文档** —— 描述的是系统当前实际在做什么。
> 整理日期 2026-08-02。改动数据流向的代码时请同步更新此文件。
>
> 配置随 `.env` 可变，下表按线上当前配置（`LLM_PROVIDER=deepseek` / `STT=whisper` /
> `TTS=doubao` / `SAFETY=aliyun`）；若切换 provider（如 TTS 改用 MiniMax），接收方
> 相应变化。

## 一、发给第三方的数据

**每一句用户说的话，最多会被发给 4 个不同的第三方。**

| 接收方 | 收到什么 | 触发时机 | 用途 |
|---|---|---|---|
| **DeepSeek** | 当前消息 + 最近 24000 字对话历史 + 人格提示词 | 每次发消息 | 生成回复 |
| **DeepSeek** | 当前消息（单条） | 每个会话首句 | 场景分类 |
| **DeepSeek** | 当前消息（单条） | 每次发消息 | 情绪识别 |
| **DeepSeek** | 整轮对话逐句转录 | 点"结束"生成拍立得 | 写回信 |
| **阿里云内容安全** | 当前消息（单条） | 每次发消息 | 内容审核 |
| **硅基流动** | 录音文件（≤10MB） | 每次语音输入 | 语音转文字 |
| **火山引擎（豆包）** | AI 回复文本（清洗后） | 每次语音播放 | 语音合成 |
| **阿里云短信** | 手机号 + 验证码 | 发送验证码 | 短信下发 |

补充说明：

- DeepSeek 那四行是**同一家但四次独立调用**。写政策时可以合并成一条，但"发送次数"和
  "每次发送的内容范围"不同，若要精确描述需分开。
- 主对话发送的历史长度上限 24000 字符（`_MAX_HISTORY_CHARS`），超出部分从最早的消息
  开始丢弃。
- 阿里云用了**两把不同的 key**：内容安全和短信是两个独立账号，不共用。
- 未接入任何第三方统计 / 埋点 / 崩溃上报（已全仓库确认：无 GA、友盟、百度统计、
  Sentry、PostHog 等）。

## 二、自有服务器上存了什么

### PostgreSQL

| 表 | 字段 | 备注 |
|---|---|---|
| `users` | `external_id`（匿名标识 UUID）、`phone_number`、`password_hash`、`data_consent`、`consent_version`、`consented_at`、创建/更新时间 | 手机号明文存储；密码为哈希 |
| `conversations` | `scene`、`persona`、`ended_at`、`mood`（情绪档）、`letter`（AI 写的回信正文） | |
| `messages` | `role`、**`content`（对话正文，明文 Text）**、`safety_flag`、`emotion`、`request_id`、`is_mock`、`degraded` | |

**对话正文与手机号均为明文存储，未做应用层加密。**

### 保留期限

- 每个用户最多保留**最近 7 轮会话**，创建第 8 轮时删除最早一轮及其全部消息
  （`trim_for_user(keep=7)`）。
- **用户记录本身没有过期机制**，手机号、匿名标识、同意记录长期保留。
- 无自动删除 / 匿名化任务；用户目前**没有自助删除数据的入口**。

### Redis

| 内容 | 保留时长 |
|---|---|
| 短信验证码 | 5 分钟 |
| 发送冷却标记 | 60 秒 |
| 每日发送次数计数 | 24 小时 |
| 验证码猜错次数 | 与验证码同寿命 |
| 登录 token → 用户 ID | **30 天** |
| 用户的 token 集合（用于改密后全端下线） | 30 天 |
| 密码连续失败计数 | 15 分钟 |
| 限流计数 | 1 分钟 |

## 三、存在用户浏览器里的

| 位置 | 内容 |
|---|---|
| `localStorage` | 登录 token、**手机号（明文）**、匿名标识 `external_user_id`（UUID）、会话快照（含对话历史，TTL 24 小时） |
| `sessionStorage` | 当前会话 ID |

手机号以明文存在 `localStorage`，任何能在该页面执行脚本的人都能读到。

## 四、日志里有什么

- 手机号**已脱敏**（`138****9307`）。
- 对话正文**不进日志**，只记 `request_id` / `scene` / `persona` / 计数类信息。
- **但匿名标识 `external_user_id` 会进 nginx access log** —— 历史查看接口
  （`GET /v1/conversation/rounds`）把它放在 URL 查询串里。该标识足以调取对应用户的
  全部历史对话，日志因此属于需要保护的资产。

## 五、写政策时需要特别注意的点

1. **敏感个人信息。** 对话内容属于心理健康相关信息，在 PIPL 下属敏感个人信息，需**单独
   同意**并告知必要性及影响。

2. **匿名用户从未同意过任何协议。** 协议同意目前只在**登录环节**收集
   （`_require_terms` 仅出现在验证码登录 / 密码登录 / 重置密码三条路径）。聊天链路完全
   不检查同意状态。而产品支持不登录直接使用 —— 这部分用户的对话同样落库、同样发给上述
   全部第三方。**这是目前最大的缺口。**

3. **只有用户协议，没有隐私政策。** 现有文档为
   `docs/于你Yewne_Alpha测试用户协议_Alpha1.0.docx`（约 9500 字，含个人信息相关条款
   24 处）。用户协议与隐私政策在 PIPL 下定位不同。

4. **现有协议未具名披露第三方。** 全文出现"第三方"15 次，但 DeepSeek、阿里云、火山引擎、
   硅基流动**均未出现**。

5. **界面上协议不可访问。** `Menu.tsx` 中"服务条款 · 隐私政策"是纯文本 `<div>`，
   非链接，且无对应页面。

6. **未提供删除 / 撤回的技术入口。** 协议中提及撤回权（9 处），但代码中无对应实现，
   `set_data_consent` 支持置为 false 却无任何调用方。

## 六、本清单可能的遗漏

以下我在代码里看不到，需要运维或相关同事补充：

- 服务器日志的保存周期、访问权限、是否发往第三方日志服务
- 数据库备份的存放位置、加密状态、保留周期
- 数据库磁盘是否启用加密
- 服务器与数据库的实际访问权限清单（谁能读到对话正文）
- 各第三方（DeepSeek 等）合同中关于数据留存与用于训练的条款
- Unity 客户端（`docs/unity/`）是否有额外的数据采集
